# C — redundant work in `dotnet-crap collect` (investigation, main@1fc580e)

Status: IN PROGRESS (written incrementally).

## 1. Verified work counts (baseline, instrumented build)

Instrumentation: `src/prof.rs`, behind a new cargo feature `collect-profile` (no-op otherwise;
default build unaffected). Counters on every source read / SHA-256 / decode / tree-sitter parse /
`canonicalize`, phase timers around each collect step, report printed to stderr.
Corpora: default scale generated by `scripts/bench_workloads.py` into /tmp/inv/C-corpora
(script /tmp/inv/C-scripts/gen.py), collect run with the benchmark's copy-only replay command.

Baseline per selected file (identical for every workload; small-files/solution 500 selected files,
the single-file workloads 1):

| work unit | count/file | where |
|---|---|---|
| source reads | **8** | scan#1 read, scan#1 final verify, collect re-read for `sources`, verify after snapshot, verify after command, scan#2 read, scan#2 final verify, verify before publish |
| SHA-256 | **7** | all reads except the `sources` re-read |
| decode | **3** | scan#1, re-read, scan#2 |
| tree-sitter parse | **2** | scan#1, scan#2 |
| canonicalize | small-files 1005 total (2/file + 5), solution 1605 (3.2/file + 5), single-file 7 | scan root x2, `select` x2, cobertura root x1, and Cobertura class resolution: one per candidate (prefix candidate + root fallback both canonicalize the *same* path when the `<sources>` prefix is the root) |
| lowercase copy | 1x report bytes (0.8-4.2 MB) | `parse_document` |
| retained decoded sources | 56 KB (small) .. 556 KB (dense) | `sources` map kept until the end of collect |

The brief's estimate ("~8 reads+hashes, 2 parses") is confirmed exactly: 8 reads, 7 hashes, 3 decodes, 2 parses.

What the breakdown shows:
- **Many-file workloads (small-files, solution): file syscalls dominate.** The verify passes (3.7 s of 11.1 s on small-files),
  the source re-read (0.35 s) and the second scan (2.05 s) are all repeated read+hash.
  **Cobertura class import is the single largest phase (3.4 s on small-files)**, and it is almost
  entirely `canonicalize` + `is_file` per class candidate. When the report's `<sources>` prefix
  is the root, both the prefix candidate and the root fallback canonicalize the *same* joined path (2 per class).
- **Single-file workloads (dense, many-callables, deep): CPU dominates.** The verification scan's
  second tree-sitter parse costs 0.45-0.66 s, about 30% of total. `evidence_write` costs 57-169 ms because
  `serde_json::to_writer_pretty` writes straight to an **unbuffered** `NamedTempFile`, so every JSON token is a `write(2)`
  (314 KB of evidence on dense-file). Lowercase copy: 1.3-7 ms. DOM parse: 15-55 ms.
- Child process: 28-60 ms here (fork/exec of `/bin/sh` + `cp` under PRoot) plus up to 10 ms of polling granularity.
  Solution's 256 ms is `cp -R` of 100 report directories.

## 3. Reductions prototyped (each a separate local commit, separable in the patch)

Commits on the worktree branch (not pushed): `C0` instrumentation (feature `collect-profile`,
investigation only, drop before merging), then `C-R1`, `C-R2`, `C-R3`, `C-R4`, `C-R5`.
`/tmp/inv/C.patch` is the full diff against 1fc580e. `/tmp/inv/C-R*.patch` hold one reduction each, in apply order
(R3 depends on R1. The others are independent apart from context lines).

### R1 (a): fold the `sources` re-read into the snapshot, drop the redundant post-snapshot verify, keep line counts instead of text
- `lib.rs`: `scan` becomes a thin wrapper over `scan_impl(args, retain)`. New `pub(crate) scan_retaining` also returns
  one `ScannedFile { line_count }` per source, computed from **exactly the hashed and parsed bytes**.
- `cobertura.rs`: new `pub(crate) parse_reports_counted(root, &BTreeMap<String, usize>, reports)`. The public
  `parse_reports` (signature unchanged) computes `str::lines().count()` per source and delegates. The importer only ever used
  the source text for `contains_key` and `.lines().count()`, so the lazy per-call `line_counts` cache disappears.
- `collector.rs`: builds `sources` (now relative → line count) from the snapshot. Deletes the re-read+decode and the
  `snapshot.verify_sources()` right after the snapshot.
- Guarantee analysis:
  - The deleted verify ran directly after scan's own final `verify_sources()`, with only path-string work in between,
    so it proved nothing new.
  - The old re-read was **not** hash-checked: the text used to bound Cobertura line numbers could come from different bytes
    than the hashed ones if a file changed in between. Now the bound comes from the hashed bytes, which is *stronger*.
  - Error precedence is unchanged: the path checks (non-UTF-8, `:`/`\`) still run after the snapshot and before the command.
  - One deleted error is now unreachable from collect: the re-read's `Io` on a file that vanished right after the scan.
    The post-command verify still reports it, as `Io`.
- Effect per file: -2 reads, -1 hash, -1 decode. Memory: no decoded source text is retained past each file's scan iteration
  (56 KB-556 KB on these corpora, i.e. total source size, and it scales with the selection).

### R2 (b): copy-free case-insensitive declaration scan; iterator `only_child`
- `parse_document`: replaces `text.to_ascii_lowercase()` (a full copy of up to 16 MiB) plus three `contains` calls with one pass over
  the `<` positions that sets three flags. The flags are then checked in the original order, so precedence holds:
  DOCTYPE beats ENTITY beats stylesheet. A unit test checks the scan against `to_ascii_lowercase().contains` on edge cases.
- `only_child` no longer collects a `Vec` (it runs once per package/class/lines container).
- Effect: removes one report-sized allocation (peak memory for big reports) and 1.3-7 ms here. CPU-only, a small share.

### R3 (c): check the staged evidence against the snapshot instead of a second full `scan`
- New `pub(crate) check_coverage_against_snapshot(path, &[(relative, sha256, line_count)])` in `lib.rs`. It calls the **same**
  `evidence::read` + `evidence::validate` as scan, then for every snapshot source with an entry runs `check_binding`.
  That is the stale-hash and line-bound check, now factored out of `scan` and shared by both paths, so messages and kinds are identical.
  Entries for unselected files are ignored, as in scan.
- Collect order is otherwise unchanged: stage, fsync, check staged JSON, `snapshot.verify_sources()` (the meaningful
  pre-publish check), `validate_destination`, `persist_noclobber`.
- **What the full second scan proved and what R3 still proves:**

  | property | full re-scan (baseline) | R3 |
  |---|---|---|
  | staged JSON parses with the native reader (`deny_unknown_fields`, unique keys) | yes | yes (same fn) |
  | native validator (version, path shape, sha format, canonical line keys) | yes | yes (same fn) |
  | every evidence entry for a selected file carries that file's snapshot hash | yes (vs re-read bytes) | yes (vs snapshot hash). Bytes are re-proven unchanged by the pre-publish verify that follows |
  | evidence lines are within the source's `lines()` count | yes (re-decoded) | yes (count of the snapshot bytes) |
  | selected bytes unchanged before publish | yes (scan's verify + explicit verify) | yes (explicit verify) |
  | sources still parse without syntax errors / resource limits | re-proven by re-parse | implied: tree-sitter is deterministic and the bytes are proven identical |
  | scoring runs on the staged evidence | yes, result discarded | **no.** Scoring cannot fail: `CoverageIndex::new`/`span_coverage` are total once the validator has accepted the line keys (`expect("validated line")` is unreachable). So the only thing lost is "does not panic" on validator-accepted input, which the scan-coverage tests already cover |
  | re-selection: a `.cs` file **added** under the selection after the snapshot | parsed, which fails only if the new file happens to have a syntax error or bad path. A clean new file was silently ignored | not looked at (neither version reliably detects added files) |
  | error kind when a source changes in the narrow window *after* the post-command verify and before the pre-publish verify | could surface as `Syntax`/`Coverage "stale coverage"`/`Source` from the re-scan | always `SourceChanged` from the pre-publish verify |
- Option not implemented: if the owner wants scoring itself exercised, the cheapest form is a sidecar
  `Vec<(start, end, merged nested ranges, complexity)>` from `analysis::collect` in the snapshot, plus re-scoring with a
  `CoverageIndex` built from the staged JSON. That is about 30 lines in `analysis.rs`, which the traversal sibling owns, and it re-proves nothing
  that can fail. If added detection of new files is wanted, re-run `selection::select` and compare it to the snapshot set: cheap,
  but a semantic *strengthening* (a new behaviour), so it is the owner's call.
- Effect per file: -2 reads, -2 hashes, -1 decode, **-1 parse**, -2 canonicalize (root + select). The second tree-sitter parse
  was ~30% of single-file collect.
- Tests added: `snapshot_binding_tests` (accept bound entries and ignore unselected ones; reject stale hash, line outside, invalid
  line key, invalid JSON, version 2, each with its exact kind and message). These failure branches cannot be reached through `collect`,
  because the importer produces bound evidence, so they need direct unit tests for the mutation gate.

### R4 (d): buffer the staged evidence write
- `serde_json::to_writer_pretty` now writes through a `BufWriter` (flushed before `sync_all`). Output bytes are identical.
- Effect: dense-file `evidence_write` 169 ms → 4 ms here. On a native runner, roughly tens of thousands of small `write(2)` calls go down to
  ~40 (314 KB at an 8 KiB buffer). This is the one reduction that helps every workload, at zero semantic risk.

### R5 (d): skip duplicate Cobertura candidate canonicalization
- In `resolve_filename`, a prefix identical to an earlier prefix, or the root fallback when a prefix *is* the root, joins to the
  identical candidate path. Canonicalizing it again can neither add a candidate (it is a set) nor raise a new error.
  Coverlet writes the project root as the `<sources>` prefix, so in the benchmark the fallback hit on every class.
- Effect: canonicalize 1005 → 503 (small-files) and 1605 → 1103 (solution). Class import on small-files went 3.4 s → 1.0 s here
  (canonicalize + `is_file` are deep-path syscall storms under PRoot).
- Not taken (idea R6): skip canonicalization entirely for a lexical candidate that equals a selected source (already canonical from
  `select`). It would change behaviour if the test command swapped a directory for a symlink, so it weakens the strict-path contract. Don't.
